# Attendance Logic & Verification

## Overview

This project implements a dual-layer verification and logging pipeline designed to record student attendance quickly and accurately without double-entry errors.

The system processes RFID card scans through two coordinated stages:
1. **Firmware Stage (ESP32):** Real-time UID parsing, student matching, and in-memory session debouncing.
2. **Host Stage (Python):** Packet validation, computer-synchronized timestamping, calendar-day deduplication, and formatted spreadsheet persistence.

---

## Why Dual-Layer Verification?

A common limitation of simple RFID attendance systems is duplicate scanning:

- **Physical Bouncing / Lingering:** A student holding a card against the antenna can trigger multiple read cycles within milliseconds.
- **Microcontroller Reboots:** If the microcontroller power is interrupted, volatile RAM flags reset, risking duplicate records for cards scanned earlier that day.
- **Unregistered Credentials:** Stray or unauthorized RFID cards could inject corrupted or dummy records into the spreadsheet.

A dual-layer architecture eliminates these vulnerabilities:

```text
┌─────────────────────────────────┐
│   Layer 1: Firmware Filtering   │
│  - Instant hardware debounce    │
│  - Registry validation          │
│  - Active session memory        │
└────────────────┬────────────────┘
                 │ Clean Valid Record
                 ▼
┌─────────────────────────────────┐
│     Layer 2: Host Validation    │
│  - Calendar-day date check      │
│  - Reliable PC clock time       │
│  - Persistent Excel audit log   │
└─────────────────────────────────┘
```

---

## Stage 1: Card Detection & UID Normalization

When an RFID tag enters the 13.56 MHz RF field generated by the MFRC522:

1. The reader performs an anti-collision check (`PICC_IsNewCardPresent()` and `PICC_ReadCardSerial()`).
2. The card returns its unique serial number (typically 4 bytes for MIFARE Classic 1K).
3. The ESP32 formats the byte array into a normalized, zero-padded uppercase hex string:

```text
Raw Bytes: [0x04, 0xA3, 0x7B, 0x2C]
Normalized String: "04 A3 7B 2C"
```

---

## Stage 2: Registry Lookup & Session Debouncing

The firmware iterates through its pre-compiled `students` array:

```cpp
struct Student {
    const char* uid;
    const char* name;
};
```

### Matching & Status Outcomes:

- **Unregistered Card:** If the UID does not exist in `students[]`, the ESP32 outputs `UID is not registered` to the Serial Monitor. No serial command is sent to Python.
- **Already Scanned in Current Session:** If `attendanceMarked[i] == true`, the system reports `Attendance already marked this session`. Transmission is blocked to eliminate immediate duplicate entries.
- **First Scan in Current Session:** `attendanceMarked[i]` is flagged as `true`, and the system prepares the serial packet.

---

## Stage 3: Serial Protocol & Message Framing

To prevent diagnostic printouts (e.g., initialization text, baud messages) from polluting the spreadsheet, machine records use a dedicated delimiter header:

```text
EXCEL|<UID>|<Student Name>|<Status>
```

Example payload:

```text
EXCEL|04 A3 7B 2C|Anushka|PRESENT
```

### Protocol Rules:
- The `EXCEL|` prefix acts as an unambiguous synchronization token.
- Student names must not contain the pipe character (`|`), as it serves as the field delimiter.
- Status is fixed to `PRESENT` for accepted credentials.

---

## Stage 4: Calendar-Day Deduplication (Host Layer)

The Python daemon (`attendance_to_excel.py`) parses incoming serial lines. When an `EXCEL|` record is encountered:

1. It extracts the system date (`YYYY-MM-DD`) and time (`HH:MM:SS`) from the computer's system clock.
2. It inspects all existing rows in `attendance.xlsx`:

```python
def already_recorded(sheet, date_text, uid):
    for row in sheet.iter_rows(min_row=2, values_only=True):
        row_date, _row_time, _name, row_uid, _status = row[:5]
        if row_date == date_text and str(row_uid).strip().upper() == uid:
            return True
    return False
```

If a matching `(date, uid)` pair is found, the entry is skipped, and a notification is displayed in the terminal:

```text
Already recorded today: Anushka (UID 04 A3 7B 2C)
```

This guarantees that restarting the ESP32 or reconnecting the USB cable cannot cause duplicate attendance entries on the same date.

---

## Stage 5: Excel Persistence & Formatting

If the record passes validation, it is appended to the active sheet.

```text
Column A: Date (e.g., "2026-10-24")
Column B: Time (e.g., "09:15:32")
Column C: Student Name (e.g., "Anushka")
Column D: RFID UID (e.g., "04 A3 7B 2C")
Column E: Status (e.g., "PRESENT")
```

The script applies automated formatting:
- **Header Fill:** Professional dark navy blue (`#1F4E78`) with bold white text.
- **Column Dimensions:** Auto-adjusted to prevent truncated data.
- **Freeze Panes:** Row 1 is pinned so header titles stay visible during scrolling.
- **Auto-Filter:** Enabled across all columns for quick sorting by date or student.

## Edge Case Handling

| Scenario | System Reaction | Prevention Mechanism |
|----------|-----------------|----------------------|
| Card held on reader | Read once, then paused | 800 ms polling delay & `attendanceMarked` flag |
| ESP32 rebooted mid-day | RAM reset, but logged in Excel | Host `already_recorded()` date check prevents re-logging |
| Unknown card scanned | Serial warning only | Ignored by Python; no `EXCEL|` payload emitted |
| Workbook open in Excel | Permission error caught | Script alerts user to close file; does not crash |
| USB disconnect | Graceful exception catch | Terminal advises reconnecting without data corruption |

## Results

- **Zero Duplicate Entries:** Eliminates both rapid double-taps and post-reboot duplication.
- **Instant Response:** Card scan to Excel write takes less than 500 milliseconds.
- **Clean Audit Trail:** Timestamps reflect accurate system time with structured, filterable fields.
- **High Fault Tolerance:** Unregistered cards and file-lock collisions are handled gracefully.
